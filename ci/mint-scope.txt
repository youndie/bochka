# Why each mint failure is there. `<status> <substring of the case name or function> <reason>`.
#
# Three statuses, and the difference between them is the whole value of this file:
#
#   out-of-scope  the case asks for something S3 does not have — MinIO's admin API, its own
#                 extensions, or a signature version S3 has retired. Passing it would mean
#                 implementing somebody else's product.
#   deferred      S3 has it, we do not, and there is a task
#   defect        our answer is wrong, and there is a task
#
# A rule that stops matching is reported as STALE rather than ignored: a reason for a failure that
# no longer happens reads as true to the next person.
#
# Those three words are the whole vocabulary, and `ci/mint_scope.py` refuses any other by name
# rather than taking it: the status is the claim, and a word the script does not know is a claim it
# cannot check. Measured before the refusal existed: a rule reading `out-of-scop` was counted as
# an explanation and the run exited 0 with the typo printed where a verdict belongs.
