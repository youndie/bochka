# --- defects: bochka should pass these and does not. Each names what to do. --------------------
deferred	unicode_metadata	the signature half of this was a defect and is fixed (the canonical request is hashed as bytes now); what is left is the value round trip, and current botocore refuses to send non-ASCII metadata at all, so what to match is not established
deferred	object_read_unreadable	the premise was wrong: the key arrives as %C2%AE%C2%8A-, which is well-formed UTF-8, so this is not a malformed key but a key holding C1 control characters. Rejecting those contradicts a documented decision (Р2: keys are not restricted, and `encoding-type=url` exists because a listing must carry bytes XML cannot) and needs a better source than one case. The UTF-8 rule itself was a real gap and is now checked
defect	object_raw_response_headers	a content type set at upload came back as the default; not reproduced through the fixture yet
