# The first matching rule wins, so order is significance: put the narrow ones first. A narrow rule
# placed after a broad one that also matches is dead, and dies quietly — `object_raw_response_headers`
# sat below `object_raw` for a milestone, classified as a defect and counted as out of scope.

# Status is one of:
#   out-of-scope  — bochka does not have this and the backlog says it will not (README, "What

#                   family a finished milestone should already pass, is a sentinel. It says
#                   nothing while the cases pass and keeps the broad rule from swallowing them
#                   if they stop (see `bucket_policy_status`).
#   off-by-default — bochka does this, and the configuration this run measured does not turn it on.
#                   The reason names the switch, so the line can be checked by flipping it.
#
# A case matching nothing is reported as `unclassified`, which is the point of the file: a
# failure that nobody has looked at must not be able to hide inside a category.
